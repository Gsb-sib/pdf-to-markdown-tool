# 文字优先版本验证（2026-11-12）

默认先生成文字 Markdown；不初始化公式模型，不导出 PDF 内嵌图片。扫描页继续使用普通 ONNX OCR。公式增强仍可手动选择。

## 实际使用

1. 访问 `http://localhost:8083/`，上传 PDF，保持“文字优先”。
2. 如希望给明显的独立公式留空，改选第二种模式。标记例如 `〔待填写公式 p2-1〕`，对应 PDF 第 2 页的第 1 个占位。无需 Python 公式环境。
3. 在右侧编辑正文、补写 `$...$` 或 `$$...$$`。按钮“插入公式占位”会在光标位置加入空的 LaTeX 模板。
4. 点击“下载 .md”，保存当前编辑稿。编辑不写回服务器；ZIP 始终包含原始转换结果。
5. 需要原插图时，转换前开启“提取 PDF 内嵌图片”。若已编辑正文，将下载的 `.md` 替换 ZIP 内同名文件，并保留 `assets/`。

留空采用保守文字规则，只判断带明显数学运算符的独立行。含普通单词、中文或完整原生网格表格的内容保留。行内公式、分式、多行公式、OCR 未正确识别的公式可能漏过，无法保证所有公式都被留空。拿不准时保留原文，用户可直接在编辑区删除或补全。

## 速度与资源

同机 Windows x64、Intel Core Ultra 9 185H、约 32 GB 内存，未使用 GPU。普通 OCR 2 个线程；测试时没有调用公式模型。数值为包含上传、提取、打包及响应的整次 HTTP 耗时，使用本地接口。

| 样本 | 模式 | 页数 | HTTP 秒 |
| --- | --- | ---: | ---: |
| 单页中文与简单等式 | 文字优先 | 1 | 0.044 |
| 同一单页 | 独立公式留空 | 1 | 0.029 |
| 教材文字页 | 文字优先 | 1 | 0.118 |
| 每页仅少量文字的合成文档 | 文字优先 | 201 | 0.534 |

教材页在前轮公式增强测得 234.922 秒，本次只提取原始文字，不生成 LaTeX，两次输出目标不同，不能视为相同准确率下的加速倍数。201 页样本很简单，不能代表 201 页教材或扫描文件。未建立固定 4 MB PDF 的耗时基准，体积不能换算成固定等待时间。扫描 OCR、低质量页面的旋转重试和表格逐格识别仍可能耗时。

所有新请求明确设置 `includeImages=false`，下载 ZIP 只含 Markdown，未生成公式小图。旧任务和旧图片保留。
